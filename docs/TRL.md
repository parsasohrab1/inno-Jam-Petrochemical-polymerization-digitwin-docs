# TRL assessment (evidence-based)

**Level reached: TRL 4 for the individual components, on SYNTHETIC data only.** TRL 5 is not claimed.

`pytest` (CI on every push) runs 7 tests:

| Component (SRS item) | Module | Validated against |
|---|---|---|
| Data validation: range, rate of change, robust outlier (FR-1.5) | `validation.py` | injected spikes and NaN |
| Kinetic chain-growth model with hydrogen transfer, LSODA (FR-3.1, FR-3.4); melt index from Mw by a power law | `kinetics.py` | direction of the hydrogen effect, ODE steady Mn equals the analytic value within 1 % |
| PLS virtual sensor with R2 / RMSE / MAPE (FR-2.1, 2.2, 2.4) | `sensor.py` | hold-out R2 above 0.9, MAPE under 25 % on data generated by the kinetic model plus 3 % noise |
| Residual learning on top of the kinetic model (FR-4.1) | `sensor.ResidualModel` | with a 30 % propagation-rate bias the corrected model has less than half the RMSE of the uncorrected one |
| Set-point optimisation to a target MI, bounded SLSQP (FR-6.1, 6.2) | `sensor.optimise_setpoints` | reaches the target MI within 2 % inside the bounds |
| Anomaly detection (Isolation Forest) with Info / Warning / Critical levels (FR-8.1, 8.3) | `anomaly.py` | under 5 % non-info on normal data, over 90 % detection of a 6-sigma shift |

## Not done (and why)
- The kinetic constants are **illustrative**; the model has no molecular-weight or composition distribution (FR-3.2), no heat-transfer or hydrodynamic model (FR-3.3), no FMU export (FR-3.5), and the MI power law is a generic empirical form. All validation is against **data generated by the same kinetic model**, which shows the code is correct, not that it predicts the plant.
- **No plant or LIMS data.** Accuracy on the real reactor is unknown (TRL 5 needs real data).
- No OPC UA / MQTT / historian connectors, MLOps/model registry, dashboards, reports, RBAC/audit log, or latency tests (NFR).

## Next steps toward TRL 5
1. Historian + LIMS data for several grades under a data-sharing agreement.
2. Fit the kinetic constants, validate the PLS sensor and the residual model on held-out grades/periods, and report R2 / RMSE / MAPE on real data.
3. Add connectors and measure latency; compare the optimiser's recommendations with operator practice.
